# Правки и сообщения об ошибках

Самый полезный вклад в FrogWord — сообщение об ошибке: команда из чата, которую игра не
поняла, слово, которое не засчиталось, поле, на котором не собрать ни одного слова.
[Заведите issue](https://github.com/Aumphaadr/FrogWord/issues/new): что сделали, что
увидели и что ожидали увидеть; для веб-версии — браузер, для приложения — система. Если
дело в раунде, пригодится журнал сессии (Audit log в интерфейсе хоста). Прежде чем
выкладывать его, просмотрите: в журнале бывают ники зрителей.

Правки принимаются на условиях лицензии проекта — [MIT](LICENSE).

## Где что лежит

- [README.md](README.md) — что это за игра, как её запустить и собрать, устройство
  репозитория.
- [CHANGELOG.md](CHANGELOG.md) — что изменилось, по датам публикации.
- [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) — что взято со стороны и на каких
  условиях.
- Веб-версия: исходники — те же, что у приложения (`apps/desktop/`), собранный сайт —
  `docs/` (GitHub Pages).

## Как устроена правка

1. Правила игры живут в чистом ядре `packages/core/` — оно ничего не знает о React, Tauri,
   Twitch и SQLite. Хранилище — `packages/storage/`, интерфейс и связь с Twitch —
   `apps/desktop/src/`, оболочка Tauri — `apps/desktop/src-tauri/`. Новая логика приходит
   вместе с тестами рядом (`*.test.ts`).
2. Строка в [CHANGELOG.md](CHANGELOG.md) в разделе «Не опубликовано». Номер версии
   назначает автор проекта.
3. Если правка видна в веб-версии — `npm run build:pages`: `docs/` идёт в тот же коммит.

## Проверка перед публикацией

- `npm run typecheck` и `npm test` — без ошибок.
- `npm run check` заканчивается строкой «Все проверки пройдены»: внешние адреса, значки,
  лягушки, лицензии рядом с чужими файлами, лицензии библиотек.
- `npm run build:pages`, если менялось что-то, что видно в веб-версии, а также после смены
  зависимостей или файлов лицензий — сборка везёт их тексты в `licenses/`. Проверка на
  GitHub пересобирает `docs/` и сверяет с репозиторием.

## Правила

- **Всё своё — в репозитории.** Приложение и веб-версия ничего не грузят с других сайтов;
  `npm run check` не пропустит страницу, стиль или сценарий, который что-то грузит извне.
  В сеть игра ходит только к Twitch — за авторизацией и в чат.
- **Значки — из набора Klaarheid Icons.** Символы Юникода и эмодзи вместо значков не
  ставятся. Лягушки — не значки: маскот взят из Noto Emoji (см. THIRD-PARTY-NOTICES.md),
  фоновые лягушки нарисованы для FrogWord (`npm run frogs`).
- **Страж проверен на обратном.** Новая проверка должна падать, если сломать то, что она
  сторожит, — это проверяется руками один раз, до публикации.

## Чужие файлы

Всё, что не создано для проекта, — библиотека, шрифт, картинка, звук — добавляется, только
если:

1. лицензия разрешает свободное использование, в том числе в коммерческих продуктах, и не
   запрещает распространять файл (у бесплатных значков и картинок так бывает: «пользоваться
   можно, выкладывать нельзя» — такие не годятся, открытый репозиторий и есть
   распространение);
2. текст лицензии лежит рядом с файлом — как `Cygre-EULA.pdf` у шрифта Cygre или
   `NotoEmoji-LICENSE.txt` у маскота (это проверяет `npm run check`);
3. в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) появилась строка: что это, откуда, кто
   автор, какая лицензия и где файл лежит; если файл изменён — что именно изменено.

Всё, что нужно приложению и веб-версии, подключается своими файлами из репозитория — не с
чужих серверов, не через CDN и не прямыми ссылками на файлы репозиториев GitHub и сайтов на
GitHub Pages, в том числе набора Klaarheid: GitHub не хостинг для раздачи файлов.
`npm run check` следит за этим сам. Ссылка для перехода — `<a href="https://…">` или
`window.open(…)` — загрузкой не считается.

Библиотеки ставятся через npm и Cargo. `npm run check` сверяет лицензии всего, что уходит к
пользователю, — пакетов из `dependencies` и крейтов, которые линкуются в бинарник, — с белым
списком в `tools/licenses.mjs`. После смены зависимостей `npm run licenses` пересобирает
раздел «Библиотеки» в THIRD-PARTY-NOTICES.md и список `third-party/rust-crates.md` (нужен
Rust: список крейтов даёт `cargo tree`). Лицензия не из списка (GPL, LGPL, AGPL и подобные)
или новый крейт под MPL-2.0 — повод остановиться и решить, а не дописать исключение.

Значки берутся из набора [Klaarheid Icons](https://aumphaadr.github.io/Klaarheid-Icons/)
(MIT-0) командой

```
npm run icons:sync -- <папка набора> <имя значка> …
```

Она копирует файлы из папки `svg/fill` локальной копии набора (`git clone`) в
`apps/desktop/src/assets/icons/klaarheid/` байт в байт, пересобирает
`apps/desktop/src/icons.ts` и раздел «Значки» в THIRD-PARTY-NOTICES.md. По сети команда
ничего не качает и адрес вместо папки не примет. Без имён она обновляет значки, которые уже
лежат в папке; чтобы убрать значок, удалите его файл и запустите `npm run icons`
(`npm run check` напомнит о значках, которые нигде не используются). Руками не правятся ни
файлы значков, ни `icons.ts`, ни этот раздел: обновлённый значок снова копируется из набора.

Фоновые лягушки веб-версии строятся рецептами в `tools/frogs.mjs` на геометрическом ядре
набора — его копия лежит в `tools/klaarheid/geom.mjs` и руками не правится. После правки
рецепта — `npm run frogs`: он пересобирает `apps/desktop/src/assets/icons/frogs/` и
`icons.ts`, а `npm run check` сверяет файлы с рецептами.
